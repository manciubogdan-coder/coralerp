- Purchasing radar (`/administrativ/radar-achizitii`, rules in `src/lib/achizitii/truckRadar.ts` + `_shared/truckRadarRules.ts`) takes its need from the Achiziții forecast rows (`ClientOrdersForecast onRows`): consumption until the next arrival + buffer − projected stock; each warehouse has its own rules (deadline from the truck schedule or from each product's forecast lead time) stored per type in server-only Cloud `achizitii_radar_setari`, observed order versions in `achizitii_comenzi_istoric`, via argus `radar_*`; past days are replayed with `ordersAsOf`/`rowAsOf` (morning stock, only earlier movements/orders, 4-week average before that day). Why: one forecast rule set, no hindsight in replays, and supplier orders in the legacy DB keep no edit history.
- The radar page is mounted at `/administrativ/radar-achizitii` and `/achizitii/radar`; argus opens only its reads (`PURCHASING_RADAR_ACTIONS`) to approved Achiziții/admin users, saving radar rules stays admin-only. Why: the purchasing team sees what the manager sees but cannot change the rules it is checked against.
