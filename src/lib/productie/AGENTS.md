# Producție lib rules
- Line speed reports (`src/lib/productie/lineSpeed.ts`) divide pieces by worked session time with overlapping same-line sessions merged, compare to the line's configured hourly norm, and keep open sessions out; suspect sessions are listed and excluded only by an explicit toggle. Why: speed must reflect real working time, not calendar hours or double-counted grouped orders.
- Products received ready-packed (Cloud `productie_direct_picking`, edited in Producție settings via Argus admin actions) never go to a line: Senior import inserts them completed without a line, `useOrders` shows not-yet-started orders as completed/no line with `direct_picking`, auto-distribution skips them, and Picking treats them as ready without pool consumption. Why: goods that are only labelled must not occupy Giostra or wait for production.
- The Rețetar (`src/lib/productie/recipeBook.ts`) multiplies only mixed recipes (>1 ingredient, active latest version) by same-day Senior orders, groups by client nickname else company name before " - ", and derives gross kg from raw-material PT %; advance/reambalare orders stay out. Why: production needs one total per main client, not per store.
- Rețetar recipe edits reuse `RecipeEditDialog` (same form and hooks as Configurări → Rețete); the manual „Generează necesar” tab converts typed/uploaded lines via `manualOrders` (cartons expand to whole boxes, bax needs buc/bax) into the same sheet, kept as a browser draft and never written as production orders. Why: one recipe editor, and planned needs must not masquerade as real orders.
- Rețetar sheets are summed per main client or centralized across all stores; in the centralized view the user ticks stores (`pickedStoresOf`): ticked stores form one sheet, unticked ones a second sheet. Stores are identified by `storeLabel` (store + non-Standard delivery point). Why: production prepares a chosen set of stores together without changing the orders.
- Rețetar stock check (`stockCheck`) compares the sheets' gross need with `daily_stock_snapshots` for today/past days (current `inventory` only as a labelled fallback) and current `inventory` for future days, also showing the day's other orders (`grossNeeds`); stock is handed out sheet by sheet, stores alphabetically, to name the stores left short. Pending receptions are not added. Why: production must see before starting which raw material and which stores will not be covered.
- Rețetar substitutions (`recipeSubstitution.ts`, rules in `supabase/functions/_shared/substitutionRules.ts`, saved in Cloud `productie_retetar_inlocuiri` via the admin action `retetar_substitutions_save`) run on the sheets before the stock check: "always" rules replace a theoretical ingredient in every mixed recipe; a short ingredient takes its substitutes only from stock free after the sheets and the day's other orders, then the same recipe's other ingredients grow cheapest first (Senior NIR price/kg by raw-material code, `retetar_mp_prices`) up to the max-increase %; the uncovered rest stays in the recipe and stays reported short. The same share is replaced in every recipe using the ingredient; changed rows carry the original quantity. Why: goods still ship when stock is missing, without silently changing recipes, stealing other orders' stock or raising cost more than needed.
