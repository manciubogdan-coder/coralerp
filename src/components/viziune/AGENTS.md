- Post effects live in `Effects.tsx` (switchable, dropped on PerformanceMonitor fallback; no N8AO, it crashes on this three version). Components that spread props onto three objects (drei Sky, postprocessing effects) are created with `createElement`, not JSX. Why: the dev tagger's data-* props crash them.
- Walk mode: movement, collisions and crosshair picking (machines first, then warehouse/office areas from `walkAreas`, hidden behind walls) are pure rules in `src/lib/viziune/walk.ts`; `Walker.tsx` only reads input and moves the camera in place of OrbitControls; scene clicks are ignored while walking (`walkContext`). Why: walking can be tested without a GPU and stray clicks must not open panels.
- Warehouse panels (`WarehouseDetail.tsx`, rules in `src/lib/viziune/warehouseState.ts`): raw-material lots from inventory rows with kg/pallet from the price rules; Picking per store → product with Senior pieces/pallet (selling unit 28), preferring the store's own Senior code from `productie_baxare_magazine`; sizes come from admin-only argus `viziune_pallets`, read only for products/names on screen; products without a size are listed, never counted. Why: pallet counts must come from Senior/the rules, not guesses.
- Phones (<768px) get their own Viziune HUD: compact header with a menu, one scrolling KPI row, zone/line pickers in a bottom bar, the move pad on demand, details as a bottom sheet, wider lens in portrait, fast graphics and lower DPR by default. 3D `Html` labels use `zIndexRange` below the HUD (z-10). Why: the desktop HUD covered the whole phone screen and labels floated over panels.
- Presentation mode: tour stops, headline figures and the copilot snapshot are pure rules in `src/lib/viziune/presentation.ts`; the tour only sends slow camera commands (`slow`, auto-circle at each stop) and any scene click/wheel ends it. Argus copilot (`ArgusCopilot.tsx`) calls admin-only argus `viziune_copilot` (voice recorded in the browser and transcribed server-side, shared chat read tools and permanent memory supplement the on-screen snapshot, target checked by `_shared/viziuneCopilotRules.ts`) and `viziune_voice_stream` (Romanian voice streamed as raw 24 kHz PCM, decoded by `src/lib/viziune/pcmStream.ts` and played while it arrives; then whole-file `viziune_voice`, then the browser voice, as fallbacks). Why: historical/Senior questions need the same sources as chat, camera targets must exist, and waiting for the whole audio file delayed speech by ~7 s.
