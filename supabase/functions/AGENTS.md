- Price sheets share deterministic calculation and explicit user overrides across screen/chat/live reports; Senior pallets join article-only on selling-unit 28 (not corresponding UM), reject conflicts, and disclose denominator gaps. NIR pallet lines supply the monthly inbound count; configured MP capacities stay labeled, client network fees % come only from the rules' client fee table (store/central name match, 0% when unlisted, each store its own fee in central lists), never from invoice history; distribution is per Senior cursă (carrier FF lines "TRANSPORT DIST <cursă>" ÷ pallets invoiced to stores mapped to it by store city/county rules, a labeled proposal the user can override per store or county; invoice lines without a pallet coefficient are reported, never converted to estimated pallets). Transport uses latest prices: recent-window cost per truck/cursă ÷ longer-window load (pallets per truck/trip), never annual or closed-month averages; central-partner lists weight store cursă tariffs by delivered pallets. Supply shows per-pallet and per-kg tariffs with an explicit basis; labour is the rules' people × hour cost ÷ speed (+ overhead %), recomputed in configuredSheet, never stored as server default rates. Why: prefilled inputs without silently presenting estimates as verified commercial prices.
- Argus chat and agent runs load the same server-only, fully paginated permanent memory through `argus/memoryStore.ts`; read errors fail visibly. Why: agents must retain confirmed business rules, and unavailable memory must not masquerade as empty.
- Argus conversation recall (`argus/conversationSearch.ts`) searches and reads threads of all users, since Argus is admin-only; own-thread ownership checks stay on writes. Why: admins must reuse work done with colleagues.
- Saved live reports (`argus/liveReports.ts`, template `live_spec`) refresh by code only: a parameterized Senior SELECT or a price sheet, never an AI call; the model is used once at save time to turn literal dates/names into placeholders. Why: repeated reports must not burn AI credits.
- Supply transport load (pallets per truck) comes entirely from Coral raw-material supplier orders: pallets = ordered kg ÷ range kg/palet (configuredRawPalletKg), trucks = each delivery day's pallets (all suppliers) ÷ the configured truck capacity (`truckPallets` in the price rules, default `TRUCK_PALLETS`) rounded up; never NIR PALET lines or invoice truck counts, products without a norm are listed, not counted. Why: NIR pallet lines mixed empty-pallet purchases and missed suppliers that do not invoice pallets.
- Price calculator client scopes (`_shared/priceScope.ts`) read the partner's fiscal code/central name once and inline them as escaped literals; never put correlated partner subqueries in sales WHERE clauses. Why: per-row subqueries pushed large chains past the Senior reader's 25 s limit.
- Semi-finished goods resold as they are (`tradedGood()` in `_shared/priceSourceRules.ts`, list `tradedGoods` in the price rules) are recipe components of kind `marfa`: NIR price like raw material, supply pallets = pieces ÷ configured pieces/pallet, and `tradedGood` products get only the line overhead, never direct labour unless typed. Why: bought-in goods are not processed but still travel on supply trucks.
- Price calculator rules (labour lines, pallet norms, traded goods, truck capacity, cursă pairs and city/county maps, client network fees, default margin/EUR buffer/extra loss, cost/load windows) live in Cloud `argus_price_rules` (append-only, latest row active) via `_shared/priceRules.ts`; `price_options`/`price_list` load them every run and return them so the screen sets the same active rules; code constants are only the initial defaults and built-in lines cannot be deleted. Why: the user edits rules without code changes, and server and screen must compute identically.

- Price sheets: margin % and profit % are shares of the selling price without fees: price = (production cost + distribution) ÷ (1 − margin% − profit%); minimum price (break-even) = cost + margin; network fees added last: proposed = price ÷ (1 − fee%); real profitability = (price − fees − minimum) ÷ (price − fees). Why: the user prices margin and profit from sales, not as markup on cost.
- Recipe case audit (`_shared/recipeCaseAudit.ts`, rules in `recipeCaseRules.ts`) checks every active Senior recipe (calculator's version choice) and flags version Cantitate 1 whose own components prove several pieces (containers/labels >1, or kg ÷ grams in name); kilo products and odd label counts are separate statuses; CT_CantitateBAX is shown only as context. Why: the user's rule is "components for N pieces but lei/bax = lei/buc"; invoice case content alone gave false positives.
- Senior `sql` live reads return at most 500 rows: any read that can exceed it must use `seniorSqlAll` (stable ORDER BY + OFFSET pages). Why: the bridge truncates silently.
- Partner mirror (`_shared/partnerMirror.ts`, maths in `partnerMirrorMath.ts`, screen Calculator preț → Oglindă parteneri) takes real qty/value per central partner × product from Senior invoices in the chosen period and costs them with today's price-list sheets (`price_list` per partner); incomplete sheets are listed, never counted. Reverse target cost = price × (1 − fee%) × (1 − margin% − profit%). Why: show who loses money at real prices and what must be cut when the retailer fixes the price.
- Senior estimate absorption (`ingest-erp-orders/absorb.ts`) runs once per import after all lines, from one paginated read of the touched production days paired in memory (never per-line queries, which hit CPU limits): a later Senior order (higher number) for the same store, product and production day with quantity within ±20% absorbs the earlier one — sessions/rebut/traceability move to it, the old row is zeroed and listed in Cloud `productie_comenzi_absorbite` so syncs never reopen it; bigger differences stay separate top-ups; surplus produced goes to restock. Why: Senior has no estimate flag and estimates must not be produced twice.
- Argus chat runs on `anthropic/claude-sonnet-5` (messages surface) without client abort; `consumeSseStream` + waitUntil finish and save the answer after the browser leaves, and the app-wide `ArgusBackgroundWatcher` polls pending threads to notify with a link. Why: long answers must survive tab/page changes and the user must be told when they are ready.
- Cost structure tab (`src/lib/argus/costStructure.ts`, screen Calculator preț → Structură & scenarii) weights today's price-sheet costs per piece by real Senior invoice quantities (partner_mirror_sales + price_list), excludes incomplete sheets visibly, and applies what-if % per cost line, price, volume and fee points; each cost line has a fixed share (defaults in `DEFAULT_FIXED`, editable) that never shrinks with volume or dropped partners, so dropping a client costs its contribution margin, not its paper profit; the recipe PT loss is split out of raw material into its own line, the sheet gross margin is a 100%-fixed cost line (so profit matches the price list: invoiced price − fees − minimum price), distribution is variable by default (dedicated trucks leave with the client), sales below the sheet minimum price are listed per partner; real loss % of raw material is added on top; row details compare with the live Senior journal (accounts in `ACCOUNTS`, company-wide, labelled). Scenarios are browser-saved and exported as a P&L-shaped sheet. Why: decisions must show overhead re-absorption, and theory must be checked against the books.
- Offers to another client (`OfferToClient.tsx`, action `price_history`) reuse the price_list engine for the target partner (its cursă and network fee) plus the target's whole Senior invoice history; Moldova points without trips of their own cursă take the Moldova cursă that has trips (the Linella truck). Why: export offers need real transport and past prices, not the source client's.
