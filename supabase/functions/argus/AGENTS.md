- Argus chat and agent runs load the same server-only, fully paginated permanent memory through `argus/memoryStore.ts`; read errors fail visibly. Why: agents must retain confirmed business rules, and unavailable memory must not masquerade as empty.
- Argus conversation recall (`argus/conversationSearch.ts`) searches all candidate threads and paginates their messages and owner lookup (up to 15 matching results), since Argus is admin-only; own-thread ownership checks stay on writes. Why: admins must reuse work done with colleagues without false negatives from early history/activity caps.
- Saved live reports (`argus/liveReports.ts`, template `live_spec`) refresh by code only: a parameterized Senior SELECT or a price sheet, never an AI call; generic Senior tools, live SQL reports and CEO SQL templates use `_shared/senior.ts` `verifiedSeniorRows`, retain every returned row below the bridge ceiling and reject ceiling-sized/unexpected results; the model is used once at save time to turn literal dates/names into placeholders. Why: repeated reports must not burn AI credits or present truncated data as complete totals.
- Argus chat runs on `anthropic/claude-sonnet-5` (messages surface) without client abort; `consumeSseStream` + waitUntil finish and save the answer after the browser leaves, and the app-wide `ArgusBackgroundWatcher` polls pending threads to notify with a link. Why: long answers must survive tab/page changes and the user must be told when they are ready.
- Chat and Viziune share read-only tools via `readTools.ts` and business instructions via `instructions.ts`; the explicit business table allowlist in `_shared/appData.ts` covers each warehouse, finished goods and business Cloud modules, while schema lookup returns real keys only (no row values or sensitive configuration tables); the admin-only copilot uses native Gateway messages, shared permanent memory, compact sequential tool results and JSON whitespace heartbeats, never write tools. Why: voice questions need the same historical/Senior figures without guessing columns, duplicating access rules or enabling unconfirmed changes.
- Empty microphone transcripts return HTTP 200 `needs_audio` via `_shared/copilotTranscription.ts`; the panel shows a retry notice without adding an error turn or starting analysis/speech. Why: silence is recoverable input, not a failed application request.
- Stock/coverage reads in chat, copilot, agents and CEO assistant use `_shared/purchasingForecast.ts` (compatibility export `forecastTool.ts`) and `_shared/forecastProjectionRules.ts`, also imported by Achiziții; first-step tool choice is enforced for warehouse questions, not explicit Senior accounting or finished-goods questions, and mixed questions may continue to other read tools. Why: physical stock, dated opening, weekday consumption and day-specific deliveries must not be replaced by unrelated totals or a generic mean.
